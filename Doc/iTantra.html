Part I · Section 01

The night the radio
stayed silent

Every engineering decision in this document traces back to one physical fact. It is easier to understand that fact as a story than as a number.

It is 2 a.m. in the Mahanadi delta. The water has been rising for nine hours. A relief team of four is on an embankment eleven kilometres from the nearest road, and the mobile towers went down before midnight. What they carry is a handheld radio set — the kind that works when everything else has failed, because it needs no infrastructure at all, just a battery and an antenna.

The team leader needs to say eight words to base: two people injured, we need a boat, sector seventeen. He presses the transmit key. The link is a narrowband data channel — a few hundred bits per second, all that the terrain, the power budget and the spectrum allocation will allow.

Nothing intelligible comes out the other end. Not because the radio is broken. Because human speech, as audio, does not fit.

Why the audio does not fit

Sound is a demanding thing to transmit. To reproduce a human voice with enough fidelity that words remain distinguishable, a microphone must sample air pressure sixteen thousand times a second, and each of those samples needs sixteen bits. That is a quarter of a million bits for every second of speech.

Modern codecs work miracles on that figure. Opus, the best open-source speech codec available, can carry an intelligible voice at six thousand bits per second — a forty-fold reduction, at the cost of a thin, robotic timbre. It is a genuinely remarkable piece of engineering.

It is also still ten to twenty times too much for the link in the story.

256 000
bits/sec — raw speech
6 000
bits/sec — Opus floor
300
bits/sec — the link

This is not a software problem that a cleverer codec will eventually solve. It is a bound. Audio codecs compress the waveform — the shape of the pressure wave — and a waveform detailed enough to be understood has an irreducible size. You can approach that bound. You cannot cross it by a factor of twenty.

The move that changes the problem

So stop transmitting the waveform.

The sentence two people injured, we need a boat, sector seventeen carries perhaps forty bytes of actual information. Everything else in those three seconds of audio — the speaker's timbre, the wind behind him, the exact pitch contour, the room acoustics — is not the message. It is the carrier the message arrived in.

If the phone in his hand converts that speech to text before transmission, and the phone at base converts the text back to speech after reception, then what crosses the radio link is forty bytes instead of ninety-six thousand. The two humans still only ever speak and listen. Neither of them reads or types anything. Between them, the message travels as language rather than as sound.

We are not transmitting audio.
We are transmitting meaning.

The entire thesis, in eight words

Why this must be speech at both ends

A reasonable objection: if the message is text anyway, why not simply let people type it? The problem statement answers this directly, and the answer is the reason the project exists rather than merely being clever.

  • Literacy. A system that requires typing excludes the people most likely to need it. In a disaster the person with critical information is a fisherman, a farmer, a village elder — not necessarily someone who can compose a message in a script under stress.
  • Hands and eyes. A soldier at altitude wearing gloves, a rescuer on a rope, a driver — none of them can type. All of them can press one large button and talk.
  • Speed under stress. Speaking a sentence takes three seconds. Typing it in Devanagari on a phone keyboard, in the dark, with cold hands, takes forty — if it happens at all.
  • Language. Ten Indian languages, ten scripts. Voice is the only interface that is equally native to all of them.

So the interface is voice, because voice is inclusive. The transmission is text, because text fits. iTantra is the machine that sits between the two.

What we are building

An Android application that turns two ordinary phones — or a phone and a radio module — into a walkie-talkie in which speech is converted to text on the sending device, transmitted as a few dozen bytes, and converted back to speech on the receiving device. Ten Indian languages. Entirely offline. No cloud, no SIM, no proprietary SDK.

3.2 Three levels of compression

The system does not use one compression scheme; it degrades gracefully through three, choosing the most aggressive one the situation allows.

Level 1 — Semantic transcoding

Speech becomes UTF-8 text. This is where the enormous ratio comes from: roughly 770 to 1 before any further work. Everything below is refinement.

Level 2 — Script packing

UTF-8 encodes Devanagari, Tamil, Kannada and the other Indic scripts at three bytes per character — expensive, because UTF-8 is designed to represent all scripts at once. But the frame header already declares which language this message is in. Given that, the receiver knows exactly which codepoint block applies, and roughly seventy code points cover ordinary running text in any single Indic script. We therefore remap each script into a private single-byte alphabet, and unpack it at the far end. Three bytes become one. The transformation is lossless, table-driven, costs microseconds, and is unique to the fact that we control both endpoints.

Level 3 — Template codes

In an emergency, vocabulary is small and predictable. A shared table maps the most common operational sentences to single-byte identifiers.

0x01  We need medical assistance
0x02  Fire — evacuate immediately
0x03  Position secure, no casualties
0x04  Send a boat
0x05  Request immediate extraction
...   up to 255 entries per deployment profile

After recognition, the resulting text is fuzzy-matched against this table. On a confident match the system transmits the identifier rather than the sentence — a single byte. The receiver's table renders the full sentence and speaks it. On a weak match it falls back to Level 2 automatically. The user is never aware of the switch.

A consequence worth noticing

Because each device holds the template table in all ten languages, a message sent as a template code is spoken in whatever language the receiver has selected. A Hindi speaker's alert reaches a Tamil speaker in Tamil — with no translation model, no additional download, and no additional latency. Cross-language operation falls out of the compression scheme for free.

3.3 What we lose, and how we compensate

4.3 Threading and lifecycle

Audio work must never touch the user-interface thread, and the recogniser must never block capture. Four threads, with bounded queues between them:

ThreadPriorityDuty
CaptureURGENT_AUDIOReads 20 ms blocks from AudioRecord, runs the energy gate and VAD, pushes speech blocks into the ASR queue. Must never allocate.
InferenceAUDIODrains the ASR queue, runs encoder and decoder, emits partial and final hypotheses.
LinkDEFAULTBlocking socket reads and writes, framing, retransmission timers, heartbeat.
SynthesisAUDIOChunked TTS generation feeding an AudioTrack in streaming mode.

The whole engine lives in a foreground service with a persistent notification, so that Android does not reclaim it while the screen is off — which is the normal operating state for a radio.

Cold start

Loading the acoustic and synthesis models costs one to two seconds. That delay must never be paid when the user presses transmit. Models are loaded when the service starts and held resident; the idle path keeps them warm but does no inference.

Part II · Section 05

The listening
engine

Speech recognition carries the largest share of the accuracy mark and the largest share of the compute budget. It is also where the idle-power score is won or lost.

5.1 Three-tier voice activity detection

Running the acoustic model continuously would exhaust the battery in about two hours and would fail the efficiency criterion outright. Detection is therefore tiered, so that the expensive stage runs only when the cheap stages agree that a human is speaking.

TierMechanismCost per 20 msPurpose
0Energy gate — sum of squares against an adaptive noise floor~ 3 µsRejects true silence, which is the overwhelming majority of elapsed time. Effectively free.
1Silero VAD, 1.8 MB ONNX~ 300 µsDistinguishes human speech from door slams, engines, wind and music. Prevents false wake-ups.
2Conformer acoustic model~ 4 msActual recognition. Runs only while tier 1 reports speech.

With a duty cycle typical of radio use — speech perhaps five per cent of the time — measured idle CPU should sit below two per cent of one core. That figure is to be measured with Perfetto on the target handset and reported.

5.2 Endpointing — deciding when a sentence has ended

The problem statement asks for activation “after detecting pauses and stoppages” and for the system to “form the sentences detected”. This is the endpointing state machine.

The single largest latency term

The 400 ms silence window is the biggest component of end-to-end delay, and it is a design choice rather than a computational cost. In push-to-talk mode the key release replaces it entirely, which is why PTT mode is measurably faster than phone mode — a point worth demonstrating live.

5.3 From pressure wave to text

Feature extraction

Raw samples are an inefficient representation. Audio is cut into 25 ms windows every 10 ms; each window is transformed to the frequency domain and projected onto 80 mel bands, which are spaced the way human hearing resolves pitch. Three seconds of speech becomes a 300 × 80 matrix — a compact spectro-temporal fingerprint. Cost is roughly one millisecond, computed in native code.

Acoustic model

The feature matrix is consumed by a Conformer encoder: convolutional blocks that detect local acoustic events such as plosive bursts and formant transitions, interleaved with self-attention blocks that supply sentence-level context. Output is a sequence of 512-dimensional frame embeddings. This stage is approximately eighty-five per cent of the inference cost.

Decoding

A transducer or CTC head projects each frame onto a vocabulary of roughly one thousand sub-word tokens defined in the language's token table. Beam search selects the most probable token sequence; repeated and blank emissions collapse, and the surviving tokens are joined into text.

Contextual biasing — the highest-yield accuracy work

Decoding scores are boosted for a supplied phrase list. In a distress context the critical vocabulary is small and known in advance: मदद, घायल, आग, निकासी, unit callsigns, sector numbers, local place names. Loading a domain lexicon and a deployment gazetteer measurably reduces error on precisely the words whose misrecognition would be most costly, and requires no retraining. Demonstrating the same audio decoded with biasing off and on is one of the strongest live comparisons available to us.

Part II · Section 06

The speaking
engine

Synthesis is scored on intelligibility and natural flow. Two of the four stages below are ordinary software engineering rather than machine learning, and they account for most of the perceived quality.

6.1 Text normalisation

No neural synthesiser handles raw digits, units or abbreviations correctly, and these are exactly what operational messages contain. A per-language rule file runs before synthesis.

InputNaïve outputCorrect output
112one hundred and twelveएक · एक · दो  — digit-wise, because it is a number to dial
5 kmfive k mपाँच किलोमीटर
Sector 17sector seventeenसेक्टर सत्रह
14:30fourteen colon thirtyदोपहर दो बजकर तीस मिनट

Distinguishing a quantity from an identifier is a rule, not a model: bare digit runs following a dialling or callsign context are read digit-wise, quantities followed by a unit are read as numbers. Cheap to implement, and it is the difference between a synthesiser that sounds professional and one that sounds broken.

6.2 Phonemisation

Letters are not sounds. espeak-ng converts orthography to phoneme sequences — मदद to /m ə d ə d/ — which are then mapped to integer identifiers. Indic scripts are largely phonetic, which makes this stage far more reliable for our ten languages than it would be for English.

Licence note

espeak-ng is GPL-3.0. This is acceptable for an open-source submission and is recorded in the licence inventory, but it constrains any future closed-source derivative and must be disclosed rather than discovered.

6.3 VITS synthesis

Earlier architectures required two models — text to spectrogram, then spectrogram to waveform — and were too slow for phones. VITS performs both in a single pass:

  • A text encoder transforms phoneme identifiers into latent representations.
  • A duration predictor assigns a length to each phoneme. This is the stage that produces natural rhythm, and it is why VITS output does not sound metronomic.
  • A flow-based decoder and vocoder generates the waveform directly at 22 050 samples per second.

Measured real-time factor on entry-tier ARM is approximately 0.15 — one second of speech synthesised in about 150 milliseconds.

6.4 Chunked synthesis and streaming playout

Synthesising a complete sentence and then playing it wastes the entire synthesis duration as latency. Instead the sentence is split at clause boundaries; the first chunk is synthesised and playback begins immediately while subsequent chunks are generated against the playing clock.

NAÏVE │◄──────── synthesise whole sentence ────────►│◄─ play ─►│ 0 700 ms time to first audio: 700 ms CHUNKED │◄ chunk 1 ►│◄ chunk 2 ►│◄ chunk 3 ►│ 0 180 ms │◄──────────── play ─────────────►│ time to first audio: 180 ms

Total synthesis work is unchanged; perceived latency falls by roughly seventy-five per cent. Since the rubric measures “time delay between the text received and audio processed and played”, this optimisation is directly worth marks.

Part II · Section 07

The transport
layer

Four physical media, one interface. The application never learns which one is carrying its bytes.

7.1 The abstraction

interface Link {
    suspend fun send(frame: ByteArray)
    val incoming: Flow<ByteArray>
    val state: StateFlow<LinkState>      // IDLE · DISCOVERING · CONNECTED · DEGRADED · ERROR
    val mtu: Int
    val metrics: LinkMetrics             // rssi, round-trip, loss, queue depth
}

Four implementations satisfy this contract. Changing transport is a settings toggle, and adding one costs a single file. This abstraction is also what allows the entire transport layer to be developed and tested in week one, before any model exists — a text field replaces the recogniser, and the whole path is exercised.

7.2 Bluetooth Classic — RFCOMM

RFCOMM is a virtual serial cable. It is the primary transport for two reasons: it is a reliable ordered byte stream requiring no additional protocol work, and it is the same profile that an ESP32 or a radio modem exposes. The code that talks to another phone is the code that talks to a radio.

val ITANTRA_UUID = UUID.fromString("8ce255c0-200a-11e0-ac64-0800200c9a66")

// host
val server = adapter.listenUsingRfcommWithServiceRecord("iTantra", ITANTRA_UUID)
val socket = server.accept(); server.close()

// peer
adapter.cancelDiscovery()                         // discovery cripples throughput
val socket = device.createRfcommSocketToServiceRecord(ITANTRA_UUID).apply { connect() }

7.3 Bluetooth Low Energy — GATT

BLE is not a stream but a set of addressable characteristics. One characteristic is written by the peer, one is notified by the host. Default MTU is 23 bytes; negotiating 247 yields roughly 244 usable, so a typical sentence fits in a single packet.

Power consumption is roughly a tenth of Bluetooth Classic, which makes BLE the correct standby transport and supports the multi-hour battery claim. It is also natively broadcast, which makes group operation straightforward.

7.4 Wi-Fi — Direct or hosted network

Two mechanisms produce the same result: an isolated local network between the devices, with no router, no SIM and no internet. Wi-Fi Direct negotiates a group automatically through WifiP2pManager; a hosted network — the ordinary hotspot toggle with mobile data off — achieves the same thing with far greater reliability across manufacturers. Once either exists, transport is plain TCP.

Engineering recommendation

Prefer the hosted-network path. WifiP2pManager discovery is inconsistent across Samsung, Xiaomi and Realme builds and consumed a substantial fraction of many teams' schedules; the hosted network requires no P2P API at all. Peer discovery is then a single UDP broadcast on the subnet.

7.5 Serial — the deployment path

The fourth implementation sends identical frames over Bluetooth SPP to a radio module. The phone is unchanged; only what sits at the far end of the Bluetooth connection differs. This is the configuration the problem statement describes when it refers to a “Wi-Fi/Bluetooth connected embedded device”.

7.7 Framing over a stream

RFCOMM and TCP preserve byte order but not message boundaries. Writing 45 bytes and then 38 may be read as 20 bytes and then 63. Every frame therefore carries an explicit length, and every read loops until the declared number of bytes has arrived.

fun InputStream.readFully(buf: ByteArray) {
    var off = 0
    while (off < buf.size) {
        val n = read(buf, off, buf.size - off)
        if (n < 0) throw EOFException()
        off += n
    }
}

Omitting this loop produces a system that works on a desk and fails under load. It is the single most common defect in student implementations of this class of project.

8.2 Addressing — how the message reaches the right listener

Radio does not route; it broadcasts. Every device within range receives every transmission, and selection happens at the receiver. This is how aviation, military and amateur radio have always worked, and iTantra reproduces it in software.

fun accept(f: Frame): Boolean = when {
    f.grp != myGroup            -> false      // different channel — ignore silently
    f.dst == BROADCAST          -> true       // addressed to all units
    f.dst == myNode             -> true       // addressed to me
    else                        -> false      // someone else's traffic
}

Three bytes therefore deliver broadcast operation, private one-to-one messages, and independent channels sharing the same physical medium.

Relay

Where a device cannot reach its destination directly, intermediate devices forward the frame and decrement TTL. A seen-set of recent source and sequence pairs suppresses duplicates; without it, three mutually visible devices generate an unbounded broadcast storm.

if (f.dst != myNode && f.ttl > 0 && seen.add(f.src to f.seq))
    link.send(f.copy(ttl = f.ttl - 1))

8.3 Security

Address filtering is a convention, not a control — any device can set any destination byte. In a system whose purpose is to raise alarms, the ability to inject a fraudulent maximum-volume evacuation order is a weapon. Three measures are mandatory.

MeasurePreventsImplementation
AES-256-GCM per groupEavesdropping and forgeryPre-shared key distributed at provisioning. A device outside the group receives the radio signal, fails the authentication tag, and discards the frame without ever learning its contents. Encryption is the real address.
Sliding replay windowCapture and retransmissionA 64-entry window per sender; a sequence number already seen, or older than the window, is rejected. Without this, a recorded alert can be replayed indefinitely.
Bound sender identityImpersonationThe source identifier is inside the authenticated region, so it cannot be altered without invalidating the tag.

9.3 Interface

Inclusive design rules

  • The transmit target occupies at least a third of the screen and is reachable one-handed with gloves.
  • Every state change is confirmed by haptics and by a spoken cue, never by a text dialog alone.
  • Icons and colour carry primary meaning; text is a secondary channel.
  • Full operation with the screen off, via the hardware key.
  • High-contrast monochrome palette legible in direct sunlight.
  • Recognised text is displayed alongside the spoken output, so a literate operator can verify what the machine heard — without requiring literacy to use the system.

9.4 Provisioning

Users are not asked to enter identifiers. One device creates the group and generates a random channel identifier, an AES key and node assignments; it displays a QR code. Joining devices scan it, receive the key, and claim the next free node identifier. Display names are local. Pairing is the most common point of failure in live demonstrations, and reducing it to a scan removes that risk.

9.5 Language packs

Shipping ten languages in the installer would produce a package of roughly seven hundred megabytes and forfeit the efficiency criterion. Instead assets are modular.

B.3 Frame encoding

fun encode(text: String, lang: Int, dst: Int): ByteArray {
    val template = TemplateTable.match(text)          // Level 3
    val body = when {
        template != null -> byteArrayOf(template.id)
        else             -> ScriptPacker.pack(text, lang)   // Level 2
    }
    val payload = if (encrypted) aesGcm.seal(body, seq) else body

    return buildFrame {
        u8(MAGIC_V1)
        u8((if (template != null) TYPE_TEMPLATE else TYPE_TEXT) shl 4 or lang)
        u16(seq++)
        u8(flags)
        u16(payload.size)
        u8(myNode); u8(dst); u8(myGroup); u8(DEFAULT_TTL)
        bytes(payload)
        u16(crc16(soFar()))
    }
}

    if (!accept(f)) return@collect                       // not addressed to us
    if (!replayWindow.admit(f.src, f.seq)) return@collect // replay
    relayIfNeeded(f)

    val text = when (f.type) {
        TYPE_TEMPLATE -> TemplateTable.render(f.payload[0], myLanguage)
        else          -> ScriptPacker.unpack(f.payload, f.lang)
    }

    if (f.type == TYPE_ALERT) alertPlayer.announce(text, f.lang)
    else                      ttsPlayer.speak(text, f.lang)
}

B.5 Stream framing

fun InputStream.readFully(buf: ByteArray) {
    var off = 0
    while (off < buf.size) {
        val n = read(buf, off, buf.size - off)
        if (n < 0) throw EOFException()
        off += n
    }
}
